# API Documentation

## Overview

The project exposes a FastAPI service that generates a synthetic A/B experiment, evaluates it with the decision engine, and returns a JSON decision.

**Important:** The current API is a demonstration interface. It accepts simulation settings and generates synthetic data; it does not yet accept an existing production experiment dataset.

## Run the API locally

From the repository root:

```bash
cd api
python -m pip install -r ../requirements.txt
uvicorn app:app --reload --port 8000
```

The API documentation generated by FastAPI is available at:

- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc

The health endpoint is:

```http
GET /health
```

Example response:

```json
{
  "status": "ok",
  "service": "ab-testing-decision-engine"
}
```

## Simulate and analyze an experiment

```http
POST /simulate-and-analyze
Content-Type: application/json
```

### Request fields

| Field | Type | Default | Description |
|---|---|---:|---|
| `n_users` | integer | `50000` | Total users across both experiment arms |
| `true_control_rate` | number | `0.10` | Baseline conversion-rate parameter |
| `true_lift` | number | `0.02` | Absolute treatment-lift parameter used by the simulator |
| `srm_bias` | number | `0.0` | Global traffic-split bias passed to the simulator |
| `biased_platform` | string or null | `null` | Platform receiving additional segment-specific assignment bias |
| `segment_bias_strength` | number | `0.0` | Additional assignment bias for the selected platform |
| `n_days` | integer | `14` | Simulated experiment duration in days |
| `alpha` | number | `0.05` | Significance level passed to the decision engine |
| `min_practical_effect` | number | `0.0` | Minimum absolute effect considered practically worthwhile |
| `seed` | integer or null | `null` | Optional random seed |

The simulator also supports `traffic_split` and `covariate_correlation`, but the current API request model does not expose these settings. The simulator defaults are therefore used.

### Example request

```json
{
  "n_users": 50000,
  "true_control_rate": 0.10,
  "true_lift": 0.02,
  "srm_bias": 0.0,
  "biased_platform": null,
  "segment_bias_strength": 0.0,
  "n_days": 14,
  "alpha": 0.05,
  "min_practical_effect": 0.0,
  "seed": 42
}
```

### Response fields

| Field | Type | Description |
|---|---|---|
| `verdict` | string | Decision-engine verdict |
| `reasoning` | array of strings | Explanations associated with the decision |
| `effect_estimate` | number or null | Estimated treatment effect |
| `p_value` | number or null | p-value returned by the decision engine |
| `srm_check_passed` | boolean | Whether the SRM check passed |
| `sequential_safe_to_stop` | boolean | Sequential stopping status returned by the engine |

Illustrative response only:

```json
{
  "verdict": "SHIP",
  "reasoning": ["Illustrative explanation"],
  "effect_estimate": 0.02,
  "p_value": 0.03,
  "srm_check_passed": true,
  "sequential_safe_to_stop": true
}
```

Actual values and reasoning depend on the generated dataset and analysis.

## Error handling

The endpoint currently catches exceptions and returns HTTP 500 with the exception text in the response detail. This behavior should be reviewed before production use; raw exception messages may disclose internal implementation details.

## Current implementation notes

- CORS is configured with wildcard origins for development.
- The API currently has no explicit range constraints on the numeric request fields.
- The response does not currently include a confidence interval.
- The endpoint creates synthetic data for each request.
- The API module adjusts `sys.path` to import project modules. Import and packaging conventions may be improved in a future contribution.

## Scope and limitations

This API is intended for local demonstration and experimentation. It should not be treated as a production experimentation service without input validation, security hardening, deployment configuration, and validation of the statistical methods.
